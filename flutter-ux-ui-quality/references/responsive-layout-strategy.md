# Flutter 响应式布局与自适应策略

本文件是高保真页面冻结、Flutter 交接和多视口验收时的权威布局规范。低保真只冻结语义范围、内容优先级、交互结果和无障碍要求；不冻结精确坐标、尺寸、最终留白、图文比例或装饰位置。冻结图可以作为视觉来源，但不能替代本文件所要求的跨断点行为契约。

## 1. 先写布局契约，再画高保真

每个页面在 `design-decision.md` 或 UI brief 中填写一份布局契约，至少回答：

- 目标平台与视口范围，以及每个结构断点的可观察条件；
- 内容最大宽度、边缘 inset、列数、最小列宽和 gutter；
- 关键元素相对于哪个语义锚点对齐，宽度不足时如何换行、折叠、隐藏或改为滚动；
- 哪些区域随文档流、吸顶、固定、悬浮或随滚动离场，谁拥有滚动和点击命中；
- SafeArea、系统栏、手势区、键盘、折叠/分屏的避让和遮挡规则；
- 大字体、长文本、本地化/RTL、横屏时的可接受变化；
- 需要哪些截图、golden 或交互证据来证明上述行为。

关系和行为是冻结项；只有产品确实依赖某个固定尺寸时才冻结尺寸，并写明原因和容差。

## 2. 视口分类与断点方法

断点由“内容无法继续保持当前结构”的可验证条件决定，而不是由设备名称决定。先记录目标平台，再以 Flutter 逻辑像素宽度为默认基线；产品可按真实内容密度覆盖数值，但必须在契约中写出覆盖理由。

| 默认分类 | 宽度基线（逻辑 px） | 默认结构意图 | 典型证据 |
|---|---:|---|---|
| Compact | `< 600` | 单列、窄边距、底部/汉堡导航；次要信息进入滚动或折叠 | 360×640、390×844，含长文和大字体 |
| Medium | `600–839` | 两列仅在每列满足最小内容宽度时启用；导航可转为 rail 或保留顶部 | 600×900、768×1024，纵横屏各按风险选择 |
| Expanded | `≥ 840` | 多列或主从布局；内容受最大宽度约束，导航常驻 | 1024×768、1280×800 或产品目标桌面视口 |

这些值是起始基线，不是所有产品的一刀切规则。若某块内容的最小可读宽度为 `minItemWidth`，列数应满足 `availableWidth >= columns * minItemWidth + (columns - 1) * gutter`；不能满足时回退列数或切换结构。高度不足、横屏、桌面窗口缩放、分屏和折叠铰链可触发独立策略，即使宽度未跨断点也要记录。

每个断点必须写清：`触发条件 → 结构变化 → 内容/状态保持 → 过渡和回退 → 证据视口`。只改变字号、比例或间距而不说明结构，不能称为响应式契约。

## 3. 内容宽度、列和 gutter

默认值只用于建立可执行基线，页面可根据阅读长度、任务密度和平台惯例调整：

| 分类 | 外侧 inset | 内容最大宽度 | 默认列策略 | 默认 gutter |
|---|---:|---:|---|---:|
| Compact | 16–20 | 充满可用宽度 | 1 列；列表项可横向滚动但不强制整页横滚 | 12–16 |
| Medium | 24 | 640–720 | 1 列或 2 列；每列通常不低于 280 | 16–24 |
| Expanded | 32 | 960–1200（阅读型页面可更窄） | 2–3 列或主从；列宽由内容最小宽度决定 | 24–32 |

`ConstrainedBox`/`Center` 负责最大宽度，外侧边距负责安全呼吸空间；不要用全局比例缩放把手机坐标放大到平板。表格、代码、时间线等确需宽内容的区域应明确其横向滚动容器和键盘/屏幕阅读器语义。

## 4. 相对位置与约束规则

- 用语义锚点描述关系：如“标题与副标题基线对齐”“主 CTA 与输入区相隔一个 spacing token”“操作组贴右且在窄宽度换到下一行”。记录锚点、方向、间距 token、对齐方式、换行/折叠行为。
- 优先使用 `Row`/`Column`/`Wrap`/`Flexible`/`Expanded`/`Align`/`ConstrainedBox` 和 `Sliver` 表达约束；让父约束决定子尺寸。
- `Stack` 只用于真实叠层（徽标、渐变、拖拽层、浮动按钮等）。叠层必须有边界、命中区域、溢出处理和无叠层回退；不要用一堆 `Positioned(left/top)` 拼主布局。
- 固定宽度、固定高度或 `SizedBox` 仅在控件可证明需要（例如图标命中区域、媒体纵横比、平台规范）时使用，并写明最小/最大范围；文字和主要操作不得依赖固定高度。
- 不用图片或低保真坐标推断生产布局。效果图中的精确像素是视觉参考，契约中的相对关系和可变范围才是实现依据。

## 5. 滚动、停靠与遮挡

先为每个轴指定唯一滚动所有者。通常 `Scaffold` 的 body 或一个 `CustomScrollView` 拥有纵向滚动，横向表格/代码区才另设横向滚动。只有确有独立滚动语义时才嵌套；此时记录滚动控制器、手势竞争、`shrinkWrap` 成本和无障碍焦点顺序。

| 行为 | 契约要写的内容 | Flutter 实现提示 |
|---|---|---|
| Flow（随文档流） | 是否随内容增长、是否参与主滚动、无内容时占位 | 普通 `Column`/`Sliver`，避免人为偏移 |
| Fixed（固定） | 相对视口或 SafeArea 的边、占用高度、底部内容如何避让、键盘时行为 | `Scaffold.bottomNavigationBar`、`SafeArea` 或有明确 padding 的 overlay |
| Pinned（吸顶） | 吸顶起点、离开条件、遮挡层级、回滚时恢复规则 | `SliverAppBar(pinned: true)` 或等价约束 |
| Floating（悬浮） | 锚点、命中区、与系统/键盘的最小距离、滚动显隐 | `FloatingActionButton`/`Stack` overlay；写明内容底部 padding |

固定/悬浮元素不得遮挡最后一项、错误提示、输入光标或系统手势区；在契约中明确底部 `viewPadding + dockedHeight` 的内容避让。吸顶不是“永远显示”，必须说明滚动方向和状态变化。

## 6. SafeArea、系统栏、键盘和特殊视口

- 以 `MediaQuery` 的 `padding`/`viewPadding`/`viewInsets` 为事实来源；`SafeArea` 只包住真正需要避让的区域，避免在已经处理过的层级重复叠加 inset。
- 全屏或 edge-to-edge 页面同时记录状态栏、导航栏颜色/图标对比度和内容是否绘制到系统栏下；不能把状态栏当作普通内容间距。
- 底部手势区与固定 CTA/导航栏分别计算，确保可点击区域不落入 gesture inset；横屏时检查左右手势区。
- 键盘出现时记录 `resize`、滚动到聚焦字段、底部操作栏上移/隐藏/改为内联的选择。优先让内容滚动到焦点，不用固定 `bottom` 数值抵消键盘。
- 分屏/窗口缩放使用当前 `constraints` 重新计算，而不是缓存启动尺寸。折叠屏读取 `MediaQuery.displayFeatures`，铰链/遮挡区不可放置交互控件；可把每个 `subScreen` 作为独立约束区域，契约须说明跨缝布局是否允许。

## 7. 大字体、长文本与本地化

以默认文字比例之外的至少一个大字体档（建议 `textScaleFactor` 约 1.3–2.0）验证：标题可多行、按钮可换行、标签可折叠，不能以裁切或无意义省略解决溢出。对确需单行的短标签提供完整语义（tooltip、辅助文本或可访问名称）。

使用真实长文、复数、日期/数字格式和至少一种较长本地化字符串；RTL 页面验证起止方向、图标语义和手势。不要把英文宽度当作所有语言的上限，也不要通过全局缩小字体来“修复”翻译溢出。

## 8. 导航与组件的结构切换

断点切换应保持任务、状态和路由语义不变，但允许结构变化。常见契约示例：

- Compact 底部导航 → Medium/Expanded `NavigationRail` 或侧栏；选中状态、返回路径和深链保持一致。
- 单列筛选按钮/底部 sheet → Expanded 常驻侧栏或顶部工具区；筛选结果和清除操作位置须可发现。
- 卡片列表单列 → 两/三列网格；卡片内部操作仍按同一优先级，不能因挤压隐藏主 CTA。
- 悬浮主操作 → 在窄高/键盘/辅助技术场景改为文档流内联 CTA；改动需记录命中区和内容避让。

只在契约声明了“何时、为何、如何回退”后才实现结构切换；不能以 `if (width > x)` 散落在多个组件中而无共享断点模型。

## 9. ScreenUtil 与约束系统的边界

只有技术设计启用 UI token 档并采用 `ScreenUtil` 时，它才负责根初始化和共享尺寸 token（例如设计系统 spacing、图标基准）；它不是默认依赖或响应式布局引擎。结构和可用空间必须由 `LayoutBuilder` 的父约束、`MediaQuery.sizeOf`/`paddingOf`/`viewInsetsOf`、`Sliver` 约束和组件自身的最小/最大尺寸决定。

- 允许：根部 `ScreenUtilInit`、少量经过命名的 token、与产品视觉系统一致的字号/间距基准。
- 必须：在需要结构变化的组件边界使用 `LayoutBuilder` 或共享 breakpoint resolver；在系统避让处读取 `MediaQuery`。
- 禁止：用 `.w/.h/.sp` 逐个缩放所有坐标、依赖启动时屏幕尺寸缓存、用比例缩放掩盖溢出、用 ScreenUtil 决定导航/列数/滚动所有权。

## 10. 推荐模式、反模式与验收

推荐模式：`LayoutBuilder` + 命名断点模型；`ConstrainedBox`/`Center` 的最大宽度；`Flexible`/`Expanded`/`Wrap` 的可伸缩内容；`SafeArea` + `MediaQuery` 的系统避让；`CustomScrollView`/slivers 的长列表；单一滚动所有者；状态和路由在结构切换中复用。

反模式：整页 `FittedBox`/全局缩放；主布局由大量绝对 `Positioned` 构成；固定高度包住可变文本；`ListView` 里无理由的 `shrinkWrap` 嵌套列表；每个组件私自定义断点；只截一张手机截图就宣称响应式；只测试“缩放”而不测试导航、停靠、键盘和长内容。

### 证据矩阵（按风险选择，不要求每页制作所有高保真图）

| 风险/结构 | 最小视口证据 | 必要行为证据 |
|---|---|---|
| 普通单列复用页 | Compact + 目标平台一个基准视口 | 长内容、状态覆盖、SafeArea |
| 断点改变列数/导航 | Compact + 每个结构断点两侧（至少 Medium、Expanded 中适用者） | 结构切换、路由/选中状态、最大宽度和 gutter |
| 固定/吸顶/悬浮或复杂滚动 | 目标 Compact + 一个 Expanded | 上下滚动、回弹/显隐、底部内容不被遮挡、键盘 |
| 表单/支付/权限/高风险 | Compact + 目标平台宽度 | 大字体、长本地化、错误/恢复、键盘聚焦和系统栏 |
| 横屏/平板/折叠/分屏 | 目标方向与窗口范围 | 铰链/遮挡区、两窗独立约束、左右手势区 |

每份证据旁标注视口逻辑尺寸、文字比例、方向、状态、平台和是否键盘/系统 inset 生效。验收必须证明：无 Critical/Important 溢出或遮挡；断点结构按契约切换；固定/吸顶/悬浮行为可解释；滚动所有权明确；大字体、长文本、本地化和键盘路径通过；代码未把 ScreenUtil 当结构引擎。未覆盖的特殊平台只能标记“未验证”，不能宣称支持。
