# 多级漏斗审核机制

审核按“低成本、宽覆盖的检查在前，高成本、窄范围的专业判断在后”执行。每一级只接收上一级放行的同一候选快照；任何退回都会终止后续审核，避免失败候选继续占用专业审查资源。

## 四级漏斗

| 级别 | 目标 | 执行者 | 必须输入 | 放行结果 |
|---|---|---|---|---|
| F0 确定性过滤 | 排除编译、静态检查、测试、审计和已知回归失败 | 实现者 | 任务简报、验证命令、回归夹具 | 已通过的命令证据、候选提交、证据快照 |
| F1 变更分诊 | 快速确认快照、范围、风险、证据完整性，并只开启必要审查通道 | Controller；必要时由独立 QA 协助 | F0 输出、diff、验收标准、风险等级 | `退回实现` / `进入专业审查` / `light 自检通过`，以及通道清单 |
| F2 专项审核 | 仅对触发的专业维度作独立判断 | 对应独立审查者 | 同一候选快照、该通道所需权威输入 | 每个通道的 `approved` / `changes_requested` / `blocked` |
| F3 收敛验收 | 确认同一快照的必需结论齐全、阻塞发现已关闭，并决定集成或发布 | Controller；发布时结合 QA、技术和 Release 结论 | F1 通道清单、F2 结论、必要的集成/CI 证据 | `approved` / `changes_requested` / `blocked` |

F1 是路由门，不是一次缩小版的全量代码审查。它只检查候选是否值得进入后续审核，并记录实际变化维度、必需通道和触发原因。F3 是结论收敛门，不重复已通过通道的逐项审核，也不能替代缺失的专业结论。

## 风险等级与漏斗深度

| 风险等级 | 必经级别 | F2 最小通道 |
|---|---|---|
| `light` | F0 → F1 → F3 | 无；Controller 自检后收敛，不创建持久审核报告 |
| `standard` | F0 → F1 → F2（有行为或验收变化时）→ F3 | 行为或验收变化启用 QA；其他通道按触发条件启用 |
| `high` | F0 → F1 → F2 → F3 | QA，加上导致任务升为 `high` 的每个风险通道 |
| `release` | F0 → F1 → F2 → F3 | QA、技术、Release；Product 与视觉按变化触发 |

不得通过降低任务风险等级来跳过已触发的通道。若 F1 发现声明风险低于实际风险，先升级等级、补齐通道，再放行。

## F1 分诊顺序

1. 确认候选提交、diff 和证据哈希能够唯一标识同一快照。
2. 确认 F0 的全部必需命令实际通过；缺命令、失败输出或陈旧证据直接退回实现。
3. 将 diff 映射到任务范围和验收标准；越界改动、不可测试验收或缺失权威输入直接退回。
4. 识别变化维度，按下表生成最小审查通道清单。
5. 记录分诊结论、通道、触发原因和快照标识；并行派发互不依赖的只读通道。

## F2 通道触发

| 通道 | 触发条件 | 主要结论 |
|---|---|---|
| Product | 产品范围、业务规则、优先级、用户路径或验收目标变化 | 是否符合已确认产品意图与验收 |
| QA | 可观察行为、状态、错误恢复、测试、回归面或验收证据变化 | 功能、回归和证据是否可接受 |
| 技术 | 架构、共享契约、依赖、安全、隐私、支付、数据、迁移、性能或回滚风险变化 | 技术风险与工程约束是否可接受 |
| 视觉 | 用户可见结构、交互、文案层级、样式、资产或可访问性变化 | 视觉和交互证据是否可接受 |
| Release | 构建、签名、环境、商店、监控、发布、生产变更或回滚变化 | 发布候选是否满足发布门禁 |

一个独立审查者可以覆盖多个与其职责一致的通道，但必须分别给出覆盖范围和结论。生产者不得审核自己产出的同一维度。未触发的通道不创建 `N/A` 小节。

## 退回与定向复审

- 任一通道出现 Critical、未解决的 Important、必需证据缺失或 `changes_requested`，F3 不得批准，候选退回原分支或原 worktree 修复。
- 新候选必须重新通过 F0 和 F1。F1 根据实际 diff 重新计算通道，但不自动推翻未受影响通道的结论。
- 产品范围或验收目标变化：重审 Product 与 QA。
- 命令、测试、审计、依赖或实现变化：重审 QA；涉及技术触发项时重审技术。
- 视觉或交互变化：重审视觉；行为同时变化时重审 QA。
- 发布配置、构建产物、环境、签名、监控或回滚变化：重审 Release；影响实现或风险边界时追加 QA/技术。
- 仅链接、格式或无语义文案变化：重跑覆盖它的 F0 检查和 F1；通常无需重开 F2。

审查结论必须绑定其覆盖的快照或证据哈希。F3 只能复用“覆盖事实未变”的旧通道结论，不能复用针对另一份实现或证据的笼统批准。

## 单一审核记录

需要持久独立验收时，只维护 `docs/tasks/<task-id>/review.md`：

1. 候选快照与 F0 证据链接。
2. F1 分诊：风险等级、变化维度、必需通道、触发原因、结论。
3. F2 具名通道：审查者、覆盖范围、快照、发现、缺失证据和结论。
4. F3 收敛：有效通道、已关闭阻塞项、集成/CI 证据和最终结论。

不要另建分诊报告、审核汇总或复审报告。命令输出、截图、golden、PR 和 CI 只保存路径、链接或哈希引用。
