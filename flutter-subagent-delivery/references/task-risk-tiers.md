# 任务风险分级

先按实际风险选择流程，再创建角色、分支或工件。不要为了证明某一步“不适用”而执行该步骤。

| 等级 | 典型任务 | 默认执行方式 | 漏斗审核要求 |
|---|---|---|---|
| `light` | 文档、小修复、确定性配置调整 | 当前集成分支或普通短分支；不创建任务状态或 worktree | F0 后由 Controller 完成 F1/F3 自检；不启用 F2 |
| `standard` | 边界明确的普通功能、单模块改动 | 普通任务分支 | F1 分诊；行为或验收变化至少启用 QA 通道，再由 F3 收敛 |
| `high` | 共享架构、跨模块契约、支付、认证、迁移、复杂高保真 UI | 普通任务分支 | QA 加所有导致升级的风险通道独立验收，再由 F3 收敛 |
| `release` | 签名、分发、生产环境、完整平台矩阵和回滚 | 候选分支、PR 和 CI | QA、技术、Release 必审，Product/视觉按变化触发，再由 F3 收敛 |

出现不可逆外部修改、敏感数据、安全边界、共享生成文件或无法可靠回滚时，至少升级到 `high`。风险等级决定审查强度，不决定本地目录隔离方式。

## 并行隔离

- 单写者、顺序交接、只读并行审查、`high` 和 `release` 都使用普通分支或 PR，不创建任务状态。
- 只有多个分支必须同时写入时才创建 worktree 和短生命周期任务状态；已有未提交改动不构成 worktree 理由。
- 选择 worktree 后，一个任务只创建一个并持续使用到最终验收；不得按审查轮次重建。
- 发布验证以 PR 候选提交和干净 CI checkout 为准，不用本地收尾脚本重复 CI 门禁。

## 候选与漏斗审核

1. 先解析正确集成基线、环境、依赖和验证命令。
2. F0 在构建阶段反复执行确定性检查；未通过前不得进入分诊。
3. 检查全部通过后冻结一个候选提交和证据快照。
4. F1 核对快照、范围、风险、验收与证据，退回不合格候选，并按[多级漏斗审核机制](../../flutter-quality-review/references/review-funnel.md)生成最小 F2 通道清单。
5. F2 的 Product、QA、技术、视觉或 Release 通道针对同一快照独立审核；互不依赖的只读通道可并行。
6. F3 只收敛必需通道结论、阻塞关闭和当前层级的集成/CI 证据，不重复专业审核。
7. 修复继续使用原分支或原 worktree，重新通过 F0/F1，不重建隔离环境。
8. 只让覆盖受影响内容的审查通道失效：
   - 产品范围、验收目标变化：Product 与 QA。
   - 命令、测试矩阵、审计脚本或实现变化：QA；涉及架构时加技术审查。
   - 视觉实现变化：视觉 QA；功能行为同时变化时加 QA。
   - 链接、格式或无语义文案变化：复跑确定性检查，通常不重新审查。
9. 所有必需结论通过后，普通任务走正常分支或 PR 集成；只有并行写入任务运行一次 worktree 收尾脚本。

## 设计探索数量

- 已有品牌、参考或明确方向时，默认只产出一个全局方向或页面候选。
- 用户需要探索、方向不明确或高风险设计存在实质取舍时，产出两到三个可区分候选。
- 候选数量不是质量门禁；不得为了凑数生成近似方案。
